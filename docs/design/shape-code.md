# 形码输入：五笔 86 的方案目录与码表（2026-11-23）

## 0. 前提

- 输入方案由 `[input] input_schemes` **单选**决定（全键拼音 / 双键拼音 / 形码输入），**永不允许混合输入**：
  挂着形码码表时按键只按形码解释，不再走拼音切分、整句转换，`v` / `u` / `i` 也不是表达式 / 区位 / 符号面板
  （要用那三种面板走 `Ctrl + Alt + V` / `U` / `I`，见 `docs/design/input-modes.md`）。
  唯一例外是 **z 模式**：以 `z` 开头的输入临时交给拼音引擎（见 §4.3）。
- **临时规则**：形码方案下本地模型不参与（全键 / 双键拼音才放行），见 `docs/user/input/local-model.md`；
  形码测试完成后撤掉这条判断。
- 形码数据与方案都是**本机开发数据**：仓库根 `InputSchemes/` 在 `.gitignore` 内，不进版本库；
  `InputSchemes/ShapeCode/wubi/` 是样例，装机时由安装包或用户自己放。

## 1. 目录与文件

| 项 | 约定 |
|---|---|
| 方案目录 | **安装目录**下的 `InputSchemes\ShapeCode\`（`bundled_root()`；与双键拼音的 `InputSchemes\DoubleKeysPinyin\` 同级） |
| 一个方案 | 一个子目录：`wubi\`、`cangjie\`、`shengbi\`；**子目录名就是方案 id** |
| 方案文件 | 子目录里的 `scheme.toml`；没有 `scheme.toml` 的子目录不算方案（扫描时直接跳过） |
| 码表 | 方案文件 `[Shape] Table` 指的 TSV（缺省 `table.tsv`），相对方案目录 |
| 一级简码 | 方案文件 `[Shape] LevelOne` 指的 TSV（缺省 `level1.tsv`），文件不在就是没有一级简码 |
| 当前方案 | 方案目录下的 `use_input_scheme.cfg`，键值行 `scheme = wubi`（与双键拼音同一套文件格式与文件名） |
| 缺省方案 | `.cfg` 没写 / 指不到时取**目录名升序第一个读得出来的方案**，并把 `scheme` 行重建过去 |

```text
InputSchemes/ShapeCode/
  use_input_scheme.cfg      scheme = wubi
                            mixture_input = off
                            unique_commit = on
                            fifth_key_commit = on
  wubi/
    scheme.toml
    table.tsv
    level1.tsv
  cangjie/                  以后的方案（现在空目录，不算方案）
  shengbi/
```

## 2. `scheme.toml`

```toml
[Info]
Name = "五笔86"
Version = "1.0"
Author = "极点五笔社区数据 / 云朵输入法"

[Shape]
Table = "table.tsv"
LevelOne = "level1.tsv"
Roots = "roots.tsv"
MaxCodeLength = 4

[Options]
MixtureInput = true
UniqueCommit = true
FifthKeyCommit = true
KeyMap = true
```

| 节 / 键 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `[Info] Name` | 是 | 字符串 | 方案名（设置页 / 日志显示） |
| `[Info] Version` | 是 | 字符串 | 方案版本（只记录，暂无迁移逻辑） |
| `[Info] Author` | 否 | 字符串 | 作者 |
| `[Shape] Table` | 否 | 字符串 | 码表文件，相对方案目录；缺省 `table.tsv` |
| `[Shape] LevelOne` | 否 | 字符串 | 一级简码表，相对方案目录；缺省 `level1.tsv` |
| `[Shape] Roots` | 否 | 字符串 | 字根表（键位映射参考用），相对方案目录；缺省 `roots.tsv` |
| `[Shape] MaxCodeLength` | 否 | 整数 | 最长编码长度，1–8；缺省 4（五笔 4 键） |
| `[Options] MixtureInput` | 否 | bool | 支持「英文混输」这一项（五笔特有；没写 = 不支持） |
| `[Options] UniqueCommit` | 否 | bool | 支持「四码唯一时自动上屏」 |
| `[Options] FifthKeyCommit` | 否 | bool | 支持「第五码顶字上屏」 |
| `[Options] KeyMap` | 否 | bool | 支持「键位映射参考」（辅助窗口画字根） |

- 节名、键名**大小写不敏感**（`[info]` / `name` 也认）。
- `Name` / `Version` 缺失、`MaxCodeLength` 不是 1–8 的整数、码表读不出来或一条能用的条目都没有 → 该方案读不出来
  （日志记原因；设置页红字列出）。一个方案读不出来不影响别的方案，最坏情况退回全键拼音。

## 3. 码表与一级简码

### 3.1 `table.tsv`

一行一条，三列，UTF-8（容忍 BOM，LF / CRLF 都行）：

```text
编码<TAB>文字<TAB>权重
wqvb	你好	20
wqvb	您好	10
ggll	一	20
```

- **编码**：小写 `a`–`z`，长度 1–`MaxCodeLength`；大写 / 超长 / 空编码的行跳过并记一条 `warn`。
- **文字**：单字或词组，空的行跳过。
- **权重**：非负整数，越大越靠前；不写按 `1`；不是整数跳过。
- `#` 开头的行与空行忽略。
- 单字与词组共用一张表：五笔的一级 / 二级 / 三级简码与全码就是同一批字的多个编码。
- **权重是固定的**：纯五笔的候选只按这张表的权重排，用户选择、学习、软件默认词库都不改变它。

**当前样例**：`wubi/table.tsv`，89,250 行（单字 26,601 行、词组 62,649 行；不同编码 77,168 个；
编码长度 1 位 50 / 2 位 656 / 3 位 5,426 / 4 位 83,118；权重 5–890）。
来源 `KyleBing/rime-wubi86-jidian` 的 `wubi86_jidian.dict.yaml`（极点五笔主词库，数据许可已由维护者确认）。

### 3.2 `level1.tsv`

一行 `键<TAB>字`，25 行（`a`–`y`；**`z` 是通配键，不占一级简码**）：

```text
g	一
f	地
w	人
```

- 单键输入时，一级简码**永远排第一**（哪怕码表里同前缀的词权重更高），右侧画 `[①]` 角标
  （`Candidate::auxiliary = "①"`，与 z 模式反查码同一套渲染）。
- 一级简码的字如果也在码表里命中，去重时只留第一条（一级简码）。
- 选了它只消耗这一个键（`syllables = [键]`）。
- 格式不对的行跳过并记 `warn`；重复写同一个键时后写的顶上。

### 3.3 `roots.tsv`（键位映射参考的字根）

一行 `键<TAB>字根 字根 …`，只收**每个键最常用的代表性字根**，不是完整字根表：

```text
g	王 一 五 戋 丰
f	土 士 二 干 十 寸 雨
```

- 用普通汉字表示，不需要 `HeiTiZiGen.ttf` 那套 PUA 字根字体；
- 键位映射参考的三排键盘里，每格左上角是键、下面**最多 2 行、每行最多 4 个字根**（字根之间不空格）；
- `z` 固定显示「通配」；
- 文件可由用户直接改；改完在设置页点「应用方案」或重启输入法服务。

## 4. 查询

### 4.1 纯五笔

敲 1–4 键都拿**已经敲的整串**当前缀，命中码表里以它开头的编码（`Core` 的 `shape::Table::candidates`）：

1. 前缀范围靠二分定位（条目按编码升序、同码按权重降序存）；
2. 同一页里按**文字去重**：一个字 / 词在好几个编码下命中（`工` 有 `a` / `aaa` / `aaaa`）只留一条 ——
   优先权重高的，权重相同取**源文件里靠前的**（一级简码通常在前）；
3. 候选排序：**单字优先**（单字全部排在多字词前）→ 组内权重降序 → 编码短者优先 → 源文件顺序；
4. 最多回 `SHAPE_MAX_CANDIDATES = 500` 条（一键的前缀能命中几千条，够翻很多页了）。
5. **单键先放一级简码**（§3.2）；英文混输开着时再在中文候选后面追加英文词（§4.4）。

### 4.2 通配键 `z`

- 编码中间 / 末尾的 `z` 是**通配一位**：`fc*s` 命中 `fccs` / `fcis` 等以 `fc` 开头、第四位是 `s` 的编码。
  只通配一位，不能“零位或多位”；模式比编码短时仍按前缀算（`aaa*` 能命中 `aaaa`）。
- 拼音行里 `z` 显示成 `*`（`fc*s`），上屏匹配用 `*`；原始按键照旧是 `z`。
- 纯五笔的 `z` 不参与英文混输匹配（那串是在查码表，不是在打英文）。
- **第一个键**就是 `z` 时进 z 模式（§4.3），所以想通配第一位得先打别的键。

### 4.3 z 模式：临时拼音 + 五笔反查

`z` 后面是一段临时拼音（`zyunduo`）：

1. `z` 后面的字母交给**普通拼音引擎**（软件默认词库、用户词库、第三方词库、短语库都在这一条路上）；
2. 每条中文候选右侧标上它的**五笔完整码**（`云朵 [fcms]`，`[fcms]` 用来源角标那套字体与颜色，
   与候选之间隔一个空格）。完整码取该文字最长的编码（`的` → `rqyy`，不是一级简码 `r`）；
   表里没有这个文字（用户词、第三方词、英文词）就不标；
3. 拼音行显示敲的原文（`zyunduo`），不插 `'`、不把前导 `z` 换成 `*`；
4. 选词**整段上屏**（`z` 开头的整串都被吃掉），不留下前导 `z`；
5. z 模式不做四码唯一 / 第五码顶字（它本来就不是五笔编码）。

反查码只在这种候选上填（`Candidate::auxiliary`），纯五笔与拼音输入的候选都不会显示它。

### 4.4 英文混输

方案目录 `.cfg` 的 `mixture_input`（缺省 `off`）开着时，**纯五笔**的候选后面再追加以敲的键匹配的英文词：

- 整段英文词 + 前缀补全，大小写跟着敲的走；**不做拼错纠正**；
- 词表是用户个人英文词 + 随包英文词表（与拼音「中英混输」同一份）；
- 英文候选**追加在五笔候选之后**，不参与五笔权重排序；
- 通配码（含 `z`）不掺英文。

## 5. 上屏与学习

- 纯五笔候选是 `CandidateKind::Chinese`，`syllables` 只有一项：候选命中的那条完整编码
  （前缀命中时按「音节是敲的键的前缀」对齐，整段敲的键都会被吃掉）；一级简码的 `syllables` 是那一个键。
- z 模式候选保留拼音引擎给的来源（中文 / 整句 / 英文）；`consumed_by` 在 z 模式下**整段消费**。
- 选中、空格 / 数字上屏、退格撤回、已选文本拼成组句、输入日志与统计都复用现有路径。
- **五笔候选只按静态权重排**：`Learner` 的选择次数不参与形码排序；纯五笔也不自动造用户词
  （形码的“音节”是编码，不能拿它造带拼音读音的词）。四码唯一 / 第五码顶字见 §6。

## 6. 自动上屏（`.cfg` 的两个开关）

这三个开关（英文混输 / 四码唯一 / 第五码顶字）是**五笔特有的能力**：方案要写 `[Options]` 里对应项
才会出现在设置页、运行时也才生效。仓颉 / 声笔没写就不显示这些开关（设置页换成那个方案自己的设置项），
`.cfg` 里就算留着 `on` 也不会偷偷生效（`current_options()` 按方案能力位清掉）。

| 键 | 缺省 | 说明 |
|---|---|---|
| `unique_commit` | `on` | **四码唯一时自动上屏**：敲满 `MaxCodeLength`（五笔 4）且候选只剩一条，直接上屏，不用再按空格 |
| `fifth_key_commit` | `on` | **第五码顶字上屏**：敲满 4 码后再按一个字母，先把当前首选上屏，再把这个字母当新一段编码 |

- 英文混输开着时，**第五码顶字会被跳过**（第五个字母可能还是英文词的一部分），即使 `fifth_key_commit = on`。
- 4 码没有候选时第五码不顶任何东西，只把这 4 个无效编码丢掉、第五码重新起一段。
- 两项都只在**纯五笔**下生效（z 模式不算）。

## 7. 与拼音方案的边界

`Engine::query_inner` 的顺序：英文模式 → 双键拼音 → **形码（z 模式 / 纯五笔）** → 表达式 / 英文直输 / 全拼。

- 形码与双键拼音不会同时挂（`[input] input_schemes` 只有一个值）；都挂着时双键拼音优先。
- `Engine::expression_mode` 见到形码码表返回 `false`；`v` 是普通编码键。
- 拼音行显示**敲的编码原文**：Shift / Caps Lock 敲的大写按原样显示，匹配按小写算；通配 `z` 显示成 `*`。
- 特殊输入模式（`/` 逐字选）只给全 / 双拼用；`RouterConfig::special_input` 对形码是 `false`。
- 简拼、模糊音、整句转换、辅助码与键位映射参考都不参与纯五笔查询；
  软件默认词库 / 用户词库 / 第三方词库 / 短语库只在 z 模式下使用。
- 本地模型（临时规则）不参与形码。

## 8. 设置页

「输入 → 输入方案 = 形码输入」那块面板：

- **方案**下拉：列 `InputSchemes\ShapeCode\` 下含 `scheme.toml` 的目录（读不出来的红字列原因），
  选中写 `.cfg` 的 `scheme` 行；下面有 `[刷新方案] [应用方案] [打开方案目录]`。
- **方案自己的设置项**按 `scheme.toml` 的 `[Options]` 生成：五笔显示**英文混输**（`mixture_input`）、
  **四码唯一时自动上屏**（`unique_commit`）、**第五码顶字上屏**（`fifth_key_commit`）三个开关，
  英文混输开着时第三项置灰；另外还有 **启用键位映射参考**（`key_map_reference`）与**组合键**
  （`key_map_hotkey`）两项 —— 辅助窗口画每个键的代表性字根。没声明 `[Options]` 的方案只显示方案信息与按钮。
- 字根窗口复用双键拼音的辅助窗口：三排键盘、`asdfghjkl` 第二排没有 `;`、没有零声母表；
  格子里字根从键位下面开始排，字号比韵母小一档；`Z` 格写「通配」。
- 改完点「应用方案」，设置页把 `input_schemes` 原样再写一遍，Server 顺着配置热加载重读码表与开关。
