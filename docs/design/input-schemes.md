# 输入方案：双键拼音的方案文件（2026-10-10）

## 0. 前提

- 输入方案由 `[input] input_schemes` **单选**决定：全键拼音 / 双键拼音 / 形码输入。
  **永不允许混合输入** —— 拼音侧与形码侧互相独立、互不干扰，任何时候只有一套在跑
  （引擎侧断言；设置页也不给「两个都开」的入口）。
- 双键拼音的**键位表、零声母表、辅助码开关**都不写在 `config.toml` 里，而是写在**方案文件**里
  （**用哪份辅助码表**是用户级的选择，记在方案目录的 `use_input_scheme.cfg`，见 §2）。
- 方案文件放**安装目录**的 `InputSchemes\`（安装程序给这棵目录授了「普通用户可写」）；**不做热加载** —— 改完方案文件（或换了 `use_input_scheme.cfg`）后，
  在设置页点「**应用方案**」：它把 `input_schemes` 原样再写一遍，Server 那条「配置热加载」的路就会重读方案文件并重挂键位表；
  同时**重启输入法服务** —— 方案 `WordBank` 指的词库要重新装配才接得上（热加载不重装配词库）。

## 1. 目录与文件

| 项 | 约定 |
|---|---|
| 方案目录 | **安装目录**下的 `InputSchemes\DoubleKeysPinyin\`（`bundled_root()`；安装程序给这棵目录授了「普通用户可写」，见 `apps/windows/installer/cloudime.iss`） |
| 辅助码目录 | 方案目录下的 `AuxiliaryCodes\`；辅助码文件 `.tsv` 或 `.txt`（大小写不敏感） |
| 方案文件 | `.toml` 或 `.ini`；**不含后缀的文件名就是方案 id** |
| 同名 | `a.ini` 与 `a.toml` 同时存在 → **只认 `a.toml`** |
| 大小写 | 文件名、后缀、节名、键名一律**大小写不敏感** |
| 编码 | 一律 **UTF-8**（容忍 BOM）；不是 UTF-8 → 该方案无效 |
| 首次运行 | 目录不存在或为空时，写出**全部内置样例**（§7：首道双拼 + 小鹤双拼 + 自然码） |
| 一个都没有 | 设置页提示，输入行为退回「全键拼音」 |

## 2. 当前用哪一份：`use_input_scheme.cfg`

方案目录下一个 `use_input_scheme.cfg`，**键值行**（键名大小写不敏感，空行与 `#` / `;` 注释忽略）：

```ini
scheme = shoudao        ; 方案 id（不含后缀）
auxiliary = 首右辅助码2.0.tsv ; AuxiliaryCodes\ 下的辅助码文件名（含后缀）；留空 = 不用辅助码
mixture_input = on      ; on / off：双键拼音下要不要按敲的按键匹配英文词（中英混合输入）；缺省 on
candidate_auxiliary = off ; on / off：候选项里要不要显示辅助码（`爱情 [XH]`）；缺省 off
auxiliary_mode = per_char ; 辅助码怎么对：per_char 逐字 / double_head 半字双前 / double_tail 半字双后 / first_last 半字首尾
key_map_reference = off ; off / hotkey / always：什么时候显示「键位映射参考」（新手对着敲用）
key_map_hotkey = ctrl+f1 ; 上面选 hotkey 时用的组合键
```

- **只认 `键 = 值`**：早先那种「一行就是方案 id」的老文件**不再支持** —— 读不出来就当没有内容，走下面的重建。
- `scheme` 指不到（文件不在 / 老格式 / 目录里没这份）→ 取**按文件名升序的第一个**可用方案并**重建**该文件。
- 「找到的第一个」必须确定，所以排序规则写死：**文件名升序**（大小写不敏感）。
  内置样例里排第一的是 `shoudao` —— 所以**缺省方案就是首道双拼**。
- 重建时 `auxiliary` 沿用原值；从来没写过就给默认的 **`首右辅助码2.0.tsv`**（随包那两张首右辅助码里行数多的那份，
  见下面「随包」那条）。雨棠辅助码还没做完，**先不用它**做默认；用户自己放一份进 `AuxiliaryCodes\` 仍能选它。
- `auxiliary` 是**用户级**的选择（设置页「辅助码方案」下拉写它），**不在方案文件里**。
- `mixture_input` 也是**用户级**的（设置页双键拼音面板的「中英文混合输入」开关写它，缺省开）：
  这就是全键拼音那份 `[input] mixture_input` 在双键拼音里的分身 —— 全键拼音那份**管不着双键拼音**，
  两份各管各的。语义见 §4「英文词匹配」。
- `candidate_auxiliary` 也是**用户级**的（设置页双键拼音面板的「在候选项显示辅助码」开关写它，缺省关）：
  语义见 §4「辅助码」最后一条。设置页那份开关只在「使用辅助码」开着、且选的辅助码表读得出来时可点。
- `auxiliary_mode` 也是**用户级**的（设置页「辅助码方案」右边那个下拉写它，缺省 `per_char`）：
  四种匹配方式见 §4「辅助码的四种匹配方式」；两个下拉都在「使用辅助码」开着、且选的表读得出来时可点。
- `key_map_reference` 与 `key_map_hotkey` 也是用户级的（设置页「启用键位映射参考」下拉与「键位映射参考组合键」两个下拉写它）：
  前者三选一 —— `off` 关闭（缺省）、`hotkey` 组句里按后者那套组合键弹出 / 收起、`always` 候选窗口一出现就跟着显示；
  后者是修饰键（`ctrl` / `ctrl+alt` / `ctrl+shift` / `alt+shift`）+ 功能键（`f1`–`f12`），默认 `ctrl+f1`。
  老版本写的 `1` / `0` 仍读得出来（`1` = `hotkey`，与加这两项之前的行为一致）。见 §4.1。
- 与 `config.toml` 分工：`config.toml` 只规定**哪一类**输入方案（全键拼音 / 双键拼音 / 形码输入），
  `.cfg` 规定**双键拼音里用哪一份方案、用哪份辅助码表、要不要中英混合**。两层各管各的，不会冲突。

## 3. `[Info]` 节

| 键 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `Name` | 是 | 字符串 | 方案名称，设置页列表里显示这个名字 |
| `Version` | 是 | 字符串 | 方案版本。**迁移判据**：解析时按**最接近的旧语义容忍**（不认识的写法不判无效） |
| `Author` | 否 | 字符串 | 作者 |
| `WordBank` | 否 | 字符串 | 词库文件路径，**相对方案目录**（`..` 表示上一层）。留空 = 用软件默认词库；非空 = **默认词库整套屏蔽（含单字）**，字/词全由它提供，用户自造词库与第三方词库照旧 |

## 4. `[Auxiliary]` 节：辅助码

| 键 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `UsingAuxiliaryCodes` | 否 | bool（INI `0`/`1`） | 是否使用辅助码，缺省关 |

**没有「辅助码位置」这一项**（2026-10-15 去掉）：从前有 `Location`（`head` / `body` / `tail` / `all`），
现在辅助码**逐字对应** —— 每个字最多 4 位，敲在**它那个音节后面**：`aiPD` = 「爱」（`ai` 的按键 + 它的码 `PD`）、
`aiPDqgXH` = 「爱情」（两个字各自的码各跟在自己的音节后面）。写了 `Location` / `File` 都算**不认识的键** → 整个方案无效。

- **用哪份辅助码表不在方案文件里** —— 那是用户级的选择，记在 `use_input_scheme.cfg` 的 `auxiliary` 行、
  由设置页的「辅助码方案」下拉来改；文件都放 `AuxiliaryCodes\`。
- **随包带两张首右辅助码**（`assets/auxiliary/`，见那里的 README）：`首右辅助码2.0.tsv`（20896 行）与
  `首右plus辅助码.tsv`（8070 行）。程序首次运行时把它们**播种**进 `AuxiliaryCodes\`（同名已有就不动、用户改过的不覆盖），
  装完在设置页的下拉里直接能选到。
- 辅助码文件认 **`.tsv` / `.txt`**，一行一个 `词` + 制表符 + `辅助码`；**一个词多个码就写多行**。
  **码里的字母大小写随便写**（外面拿到的表常是小写）—— 读进来**统一转成大写**，只有大写才算辅助码：
  敲的时候必须敲大写，候选右侧显示的也是大写那份。
  码可以是好几位（`爱` → `PD`），**最长 4 位**；超了 / 格式不对（少一列、非字母、码为空）的行**跳过并记一条日志**。
- **大小写就是「拼音 / 辅助码」的分界**（定死的规则）：开了辅助码时，**小写字母 = 拼音键、大写字母 = 辅助码**。
  大写只能跟在**完整音节**后面（当那个字的辅助码，最多 4 位），或者跟在**半音节**后面 ——
  第二键跳过、直接敲辅助码也行（`yH` = 「要」只按了第一键 `y` 就敲 `H`，第二键 `d` 没打）——
  这种写法按「声母 + 码」当**简拼**记下来，所以**敲完还能接着打下一段**（`yHd`：`y` 带码 `H`，`d` 起下一段）。
  没有声母的键（`a` / `o` / `u` 这些零声母韵母的键）第一键定不下读法、凑不出简拼，那串码只能当**末尾**：
  `aH` 出得了零声母那一族（`a` / `ai` / `an` / `ao` / `ang` 都留着），后面再接着敲（`aHo`）就切不出来。
  别的位置出现大写（`RFvf` 这种混用）、以及**落单的大写**都算打错了 → 该次组句切不出来，
  候选窗口什么内容也不出（**不**再按全拼兜底）。
  **没开辅助码时不分大小写**：Shift 敲的大写仍按拼音算（`Cpan` 与 `cpan` 一样）。
- **筛选是「逐字对应」**（只筛选、不排序）：候选的每个字和敲的码按顺序对齐 —— 敲了码的那个字必须对上，
  **没敲码的字不参与**；对不上就丢掉这个候选。**敲一半也算**：敲的码是表里那条码的**前缀**就留下
  （「侧」的码是 `RS`，敲了 `R` 时候选照旧在，只是那一位还没敲完）。判定顺序：
  1. **先找词**：把敲的码按字连起来，跟词表里这个词的那条整码比（`PD` + `XH` 对「爱情」的 `PDXH`）；
     传统「一格一位」的词码（`K` + `F` 对「开发」的 `KF`）比法照旧能对上。
  2. **对不上再逐字查表**：拿那个字的码跟敲的码比。
- **开了辅助码、第一个键敲了大写**（Caps Lock / Shift 卡着）：**把它压成小写**，当正常双拼打 ——
  **只动这一个键**，后面的辅助码照旧（`YpdoYP` → `ypdoYP`）。候选窗里的拼音行、回车原样上屏也都是这一份。
  大写只能当辅助码，开头一个大写本来整段都切不出来。
- **在候选项显示辅助码**（`.cfg` 的 `candidate_auxiliary`，缺省关；开关在「辅助码方案」下面）：
  开着就在候选词右边**隔一个空格**画上那个候选的辅助码（字体与颜色跟来源角标一致）：`①爱情 [XH]`。
  **已经敲上的那几位画下划线**：拼音串 `ce` + `R` 时「侧」显示成 `侧 [RS]`（`R` 带下划线、`S` 照旧）。
  画的是**光标前那个音节**对应候选的那个字的码 ——
  - 拼音串 `ai|qg`（光标在 `ai` 后面）显示「爱」的码（`[PD]`），`aiqg|`（光标在末尾）显示「情」的码（`[XH]`）；
  - 一个音节都没打完（作用域为空）时不显示；候选里对不上那个位置的字（单字的「爱」配两个音节）也不显示；
  - 单字表里查不到、而词表里有整词码时，按「一格一位」切开取那一位（与筛选的「先找词」同一套）；
  - 开关与「使用辅助码」「选的那份辅助码表」是「与」的关系：那两样没生效时开关置灰、也不显示。
- 辅助码若把候选**筛到一个都不剩**（对不上），候选窗给一行提示：「辅助码对不上，没有候选」。

### 4.2 辅助码的四种匹配方式（`.cfg` 的 `auxiliary_mode`，2026-10-16）

`auxiliary_mode`（设置页「辅助码方案」**右边那个下拉**，与选表同一条路）四选一：

| 值 | 界面名 | 单字 | 多字词（`云` = HD、`法` = UT 时「云朵输入法」） |
|---|---|---|---|
| `per_char`（缺省） | 逐字辅助码 | 本身的码 | 每个字各一段码，跟在自己的音节后面（`aiPDqgXH`） |
| `double_head` | 半字辅助码（双前） | 本身的码 | **首字码的第一位 + 尾字码的第一位** → `HU` |
| `double_tail` | 半字辅助码（双后） | 本身的码 | 首字码的**最后一位** + 尾字码的最后一位 → `DT` |
| `first_last` | 半字辅助码（首尾） | 本身的码 | 首字码的第一位 + 尾字码的最后一位 → `HT` |

- **敲的码只认「整段输入末尾」那串大写的最后两位**（半字那三种）：`aiPqgXH` → 只看 `XH`；`aiPqgXXH` → 还是 `XH`（多敲的丢掉）；中间出现的大写
  **直接丢掉** —— 不当音节、也不当码（`aiPqgXH` 的拼音读法就是 `ai qg`）。原始按键照旧整串参与
  「中英混合输入」的英文候选匹配（那条路读的是没动过的按键，见「英文词匹配」）。
- **匹配**：把候选的码按上表**推**出来（单字取本身的码；多字词取首字与尾字的码各一位拼成两位），
  敲的那几位是它的**前缀**就留下（`H` 也能命中 `HU`）—— 与逐字一样**只筛选、不排序**；
  表里没有首字 / 尾字、推不出码的候选，敲了码就对不上、会被筛掉。
- **逐字那条路不变**：表里那整词一条码（`爱情 → PDXH`）、「一格一位」的词码都只在这一种方式下认。
- **在候选项显示辅助码**：半字三种方式下**每个候选显示它自己推出来的那条码**（跟光标位置无关，
  不像逐字那样看「光标前那个音节」）；已经敲上的那几位照旧画下划线。
- 一个词多个码（同键多义）时：首字与尾字的码**两两组合**都留着（任一个前缀命中就算）。
- 设置页那两个下拉（选表 / 选方式）只在「使用辅助码」开着、且选的表读得出来时可点。

### 英文词匹配（`use_input_scheme.cfg` 的 `mixture_input`，2026-10-15）

- **开关**：设置页双键拼音面板的「**中英文混合输入**」（写 `.cfg` 的 `mixture_input`，缺省 `on`）。
  开着才匹配英文词；**关掉一律不匹配**（一个英文候选都不出）。全键拼音那份 `[input] mixture_input`
  是另一回事，两份各管各的。
- **匹配用敲的原始按键**（不是展开出来的拼音），与「显示原始输入按键」无关：
  整段是英文词表里的词就出（`hello` → hello），拼音不像话时再给**前缀补全**（`compa` → company / companies）；
  一个音节都解不出来时也能出（这时候选里可能只剩英文）。
- **不做拼错纠正**：`hallo` 不会出 hello —— 那条「差一个字母」的猜测哪儿都没有了（`english/edit.rs` 已删）。
- 开了辅助码时：**第一个键大写 → 只把它压成小写**（见 §4），照旧是正常双拼，英文照这份开关匹配。
- 快捷候选（`rq` / `sj` / `xq`、表达式 `v1+2`）仍然只在全键拼音下有效。

设置页「双键拼音」面板里与这两件事有关的项：

- **「中英文混合输入」**（ToggleSwitch）：写 `use_input_scheme.cfg` 的 `mixture_input` 行，改完让 Server 重读。
- **「在候选项显示辅助码」**（ToggleSwitch）：写 `use_input_scheme.cfg` 的 `candidate_auxiliary` 行，
  改完让 Server 重读；在「辅助码方案」下面（见 §4）。
- **「使用辅助码」**（ToggleSwitch）：直接改写当前方案文件的 `[Auxiliary] UsingAuxiliaryCodes`
  （其余内容原样不动，TOML 写 `true`/`false`、INI 写 `1`/`0`），改完顺手让 Server 重读方案文件。
- **「辅助码方案」**（ComboBox）：列 `AuxiliaryCodes\` 下的 `.tsv` / `.txt`（第一项是「（不使用）」）；
  选中的写进 `use_input_scheme.cfg` 的 `auxiliary` 行（「（不使用）」= 留空）。缺省选 `首右辅助码2.0.tsv`（随包那份）；
  文件不在时会提示「找不到 …」，把文件放进 `AuxiliaryCodes\` 或重选一个即可。

### 4.1 「辅助窗口」：键位映射参考

- 设置页「输入 → 双键拼音 → **启用键位映射参考**」（ComboBox，写 `use_input_scheme.cfg` 的
  `key_map_reference`）选「按下组合键时」时，**组句过程中**按「**键位映射参考组合键**」那套组合键
  （同页两个下拉：修饰键 `Ctrl` / `Ctrl+Alt` / `Ctrl+Shift` / `Alt+Shift`，功能键 `F1`–`F12`；
  写 `key_map_hotkey`，默认 `Ctrl + F1`）弹出「辅助窗口」：里面是一张**键盘** ——
  三排正方形格子（`QWERTYUIOP` / `ASDFGHJKL;` / `ZXCVBNM`，第一、二排 10 个、第三排 7 个，格子紧挨着，
  **第二排比第一排右移半格、第三排再右移半格**，模仿真实键盘的错位），每格：
  - **左上角**是那颗键（浅灰，字号是韵母那行的一档小）；
  - **右上角**是这个键上的**声母** `zh` / `ch` / `sh`（**棕色 `#880015`**）；
  - **中间**是这个键上的**韵母**，一义一行（换行符分开，居中）；每行**第一颗字母**按下面这张表上色，
    其余字母黑色：`a` 红 `#F42020`、`o` 橙 `#FF8040`、`e` 绿 `#00A869`、`i` 蓝 `#48ABF8`、
    `u` 紫 `#8D3CE8`、`ü` 棕 `#880015`（例：`uang` → `u` 紫、`ang` 黑；`ang` 自己开头的 `a` 红）。
    韵母里的 ü 显示成 `ü`（方案文件写 `v`：`van` → `üan`）。

  键盘**下方**隔 8 点是一张**固定 2 行 × 6 列**的表格放 `[Shengmu]` 的**零声母**：每格一行「**按键=韵母**」
  （如 `AY=ang`），格子比键盘格子**矮三分之二、宽三分之一**（好放这一行字）；12 项正好填满。
  新手可以对着敲；再按一次收起。
  选「**始终跟随候选窗口**」时不用按键 —— 每回组句都跟候选窗一起出现；「关闭」则完全不显示。
- 窗口尺寸（不再按候选窗的形状算）：四周各留 8 点、相邻格子**共用一条 1 点的线**（不是两倍宽）、
  键盘与零声母表之间 8 点。**格子边长按目标高度反推**（三排键盘 + 表两行 + 间距 + 两边留白正好等于那个高度）：
  **竖排的目标就是候选窗口现在的高度** —— 辅助窗口跟候选窗**一样高**（候选窗底下多一行译文、多一页页码
  时它也跟着高；那些行的有无要看译文与页数，量不出来，只能跟着宿主走）；**横排**宿主又扁又宽、按不了，
  直接用「候选窗口装 9 个候选项」量出来的高度。两种排布都再夹一道**最低高度 316 物理像素** ——
  候选很少、或者屏幕缩放把目标压得很小时，辅助窗口都不比它矮（格子里的字才撑得住）。窗口**高度恒定**，
  宽度取「键盘（含错位）」与「零声母表 6 格」里宽的那个。
- 在设置页改完输入法服务会重读（与方案、辅助码方案同一条路）。
- 组合键里 `Ctrl+Alt` / `Alt+Shift` 那两套平时 DLL 不会往 Server 送（它们在系统 / 外壳那一层），
  所以 Server 会把当前这套组合键随 `InputSettings::key_map_modifiers` / `key_map_key` 下发给 DLL，
  由 DLL 在**组句里**专程把这一个键送来；没接管的照旧回 `Passthrough` 重放回应用。
  系统或应用占着同一套组合键时按不出来（设置页那行注里写了）。
- 窗口本身走**辅助窗口模板**（`server/src/ui/auxiliary_window_template`，圆角与候选窗口同源、阴影同源）：
  按**候选窗口矩形中心点所在的那半边屏**往另一边摆 —— 竖排时中心在**右半边**就贴**左侧**（否则右侧），
  横排时中心在**下半边**就贴**上方**（否则下方），最后夹进工作区。
- **候选窗一收它就收**（`always` 那种方式下，候选窗下次弹出会跟着再出现；`hotkey` 那种方式下开关回到关，
  下次要看得再按一次）；候选窗**展开**着（Tab 的「更多候选项」）时它**先让位**，Tab 收起再摆回来。

## 5. 键位与零声母（`[Shengmu]`）
- **声母**：翘舌声母占哪个键在 `Remapping` 里写（例：`v=zh`）；值里出现 `zh` / `ch` / `sh` 的项即声母。
- **韵母**：`键=韵母`，一个键对多个韵母用逗号分隔（例：`d=iang,uang`）。
- **同一键按位置分别当声母与韵母**：`v` 既是 `zh` 又是 `ü`，`i` 既是 `ch` 又是 `i`。
- **`ü` 用 `v` 键。**
- **`v` 那一族与 `u` 那一族各自独立**（2026-10-15）：`vn`（ün）与 `un`、`van`（üan）与 `uan`、
  `ve`（üe）与 `ue` 是**两两不同的韵母**，不在方案层互相转换（写哪个就是哪个）。
  `v` 是词库与方案文件里的 ü 标记，合法韵母共 36 个：`v` / `ve` / `vn` / `van` 与 `u` / `ue` / `un` / `uan` 都在表里，
  写错一个整个方案无效。辅助窗口里 `v` 显示成 `ü`（`van` → `üan`）。
- **六个韵母必须写全**（2026-10-15）：`[Remapping]` 里 `un` / `vn` / `uan` / `van` / `ue` / `ve` 一个都不能少
  —— 说不清这六个音怎么打就判无效（校验会列出缺哪几个）。**挂在哪个键上不限**，同键多义照旧
  （内置三份样例都是把 ü 那一族挂在 `u` 那一族那个键上：`un,vn` / `uan,van` / `ue,ve`）。
- **同键多义两个都匹配**（如 `t` 既是 `ve` 又是 `ue`）：两端都展开，让词库决定 —— 不是合法音节的话词库里自然没有。
- **同键多义只留合法音节**：展开出来的组合要能在普通话音节表里查到；`sh` + `iang` 这种查不到的直接丢掉 ——
  否则非法的那个会先被挑走，挡住同键另一义的 `shuang`（`ul` = 双）。
- **ü 的写法归一**（2026-10-15）：`j` / `q` / `x` / `y` 后面的 `v`（ü）一律写成 `u`。方案把 ü 那一类韵母写成
  `ve` / `v` 时（首道 `b = "ve"`），`j` + `b` 拼出来的是 `jve`，归一成标准写法 `jue` 才查得到「觉」
  （不归一就会被上一条「只留合法音节」筛掉，表现成「这个键按下去什么也没有」）；
  `l` / `n` 后面的 `v` 不动（`lve` / `nve` 本身就是词库里的写法，`略` / `虐`）。

**零声母一律写在 `[Shengmu]` 节里** —— 程序里**不再内置任何「引导方案」**（早先那四种 `natural` / A / O / E 引导已删除）。左边是零声母韵母，右边是依次要按的**两个键**：

| 项 | 约定 |
|---|---|
| 节 | `[Shengmu]`，**必填** |
| 左边（键） | 只能是可以单独成音节的韵母：`a` / `o` / `e` / `ai` / `ei` / `ao` / `ou` / `an` / `en` / `ang` / `eng` / `er` |
| 右边（值） | **正好两个字母**（大小写不敏感，按小写参与匹配） |

```toml
[Shengmu]        # `ang`（昂）依次打 A、Y
a = "AA"
e = "UE"
o = "OO"
ai = "AI"
ang = "AY"
```

- **表里没写的两键组合就不出零声母**（没写 `er` 就打不出 `er`）。
- 两键的**第一个键不必是 a/o/e**：写 `an = "BJ"` 时同一次按键既解出 `an`（零声母）也解出 `ban`（声母 b + 韵母 an），两条都进候选，让词库决定。
- TOML 里值要带引号（`a = "AA"`）；INI 里写 `a=AA`。
- 同一个两键被两个韵母占了（两组撞键）→ 整个方案无效。

- **`;` 键**：只有 `Remapping` 里**出现了 `;`**（微软 / 搜狗的 `ing`）才把它吃进组句；否则不进组句。
  中文下要打字面 `;` 用「`;` + 空格」；英文模式原样放行。
  ⚠️ 写法：TOML 的裸键不允许 `;`，要写成 `";" = "ing"`；INI 里半角 `;` 是注释，写**全角 `；`**（两种写法解析后都是同一个 `;` 键）。

- **分词**（双键拼音特有；因为辅助码的存在，单引号 `'` 在双键拼音里也能用）：
  - **没开辅助码**：**两键一个音节** —— 第二个键落下就能定分词。
  - **开了辅助码**：要到**第三个键**才能定 —— 第三键是**大写**字母就是上一个音节的**辅助码**（不分词，如 `uuC`）；
    是**小写**字母就是下一个音节的第一个键（分词）。
  - **`'` 随时能强制分词**：`uuc` 想明确切成两个音节就写 `uu'c`（解析结果：`uu'c` 分词、`uuC` 不分词）。
  - **手动分了词就能用简拼**（2026-10-16）：用 `'` 分段以后，**一段一个键**也够 —— 那个键按它的**声母**当简拼
    （按前缀查词）：`y'd` 匹配「云朵」（`y` 是「云」的声母、`d` 是「朵」的声母；末尾那段本来就算半个音节）。
    简拼后面也能跟辅助码（`yH'd`）。**不分词时仍然是「两键一个音节」**，不会按简拼读（`yd` 不是两个简拼）。
    那个键没有声母（如 `a`）时这一支不成立。

## 6. 变换流水线

按键的处理顺序（定死，不然 `Exchange` 之后按哪张表查说不清）：

1. **Exchange**（物理键互换）—— `y-z` 表示 y 与 z 两个**物理键**互换（打 z 出 y、打 y 出 z）；**仅 TOML**；**禁止链式**（`a-b` + `b-c` 不叠加）。
2. **Remapping**（逻辑键 → 声母 / 韵母）
3. **零声母**（查 `[Shengmu]`：这两键是不是某个零声母韵母）
4. **辅助码**

**「显示原始输入按键」是配置项**（`[input] show_raw_input`，**缺省开**），不在方案文件里：

- 开（缺省）：拼音行显示**原始按键**（打 `yunduo` 显示 `yp'do`，按**音节**用半角 `'` 隔开），且**未选候选直接上屏**也上屏原始键（打 `ypdo` 按回车 → 上屏 `ypdo` 而不是 `yunduo`）。
- 关：拼音行显示展开后的完整拼音（`yun'duo`），上屏照常上屏展开后的拼音。显示串里的字母数跟敲的按键数对不上，
  所以拼音行的**光标**按「这一段展开的拼音显示完」算 —— 首道打 `es` 是 `shou|`，不是拿两个按键去数展开串的前两个字。
- 作用域**只在「显示 + 上屏」这两处**；输入日志与学习照记上屏的文字。
- 设置页「双键拼音」面板里有它的开关。

**只有全键拼音才有的功能**，双键拼音下一律没有：

- 按**原始按键**认的快捷候选：`rq` / `sj` / `xq` 这些，以及表达式 `v1+2`。
- 「中英文混合输入」里的**英文尾段**（`woxiangxuehaorust` 那种「拼音 + 末尾英文词」）。

**英文词匹配双拼下也有**（按原始按键，由 `.cfg` 的 `mixture_input` 开关管，见 §4）；
拼错纠正两边都不做（`within_one_edit` 那套已随 `english/edit.rs` 一起删了）。
**候选项右侧的辅助码**也是双拼才有的（`.cfg` 的 `candidate_auxiliary`，见 §4）；

双键拼音里 `v` / `u` / `i` 只是**普通方案键**（`v` = `zh`/`ü`），不再进那三种面板 ——
连候选窗左下角那句「输入数字或表达式」提示也不会出现（`Engine::expression_mode` 见到挂着双拼表就返回 `false`）。

**按键只有方案那一种读法**（2026-10-14）：

- 解法解出的音节序列**直接就是切分**，不再交给全键拼音那套切分器重切一遍：不认**简拼**（`kai` 不会被切成 `k` + `ai`）、
  不放宽末尾音节（音节是方案解出来的，按键不会让它再长）、也不算「一处编辑的纠错读法」（那串字母不是用户敲的）。
  否则 `ceshi`（`ce` + `song` + 半个音节）会被读成 `ce'shi`，把「测试」混进候选。模糊音照旧（那是用户自己配的读音习惯）。
- 尾巴上那半个音节（只按了一个键）还不知道是什么音节，按它**可能接出**的音节**一族一份切分**、候选取**并集**：
  声母那一族收成一条前缀（首道 `g` → `g…`、`e` → `sh…`），零声母那几族**一个音节一份** ——
  首道 `u` 那几族是 `e` / `ei` / `eng`，它们互不为前缀，收成公共前缀 `e…` 会把同前缀的 `en` / `er` 也放进来。
  两族都在时两份都出（首道 `e` = `sh…` + `en` + `er`）；一个音节都接不出来时尾巴不参与，只按已经完整的音节读。
- 双拼的「覆盖了多少输入」按**按键数**算（不是展开出来的拼音字母数）：同一段按键的几种切法得用同一把尺子量，
  不然半个音节的几种猜法会互相压（`a` 的 `ang` 比 `a` 长，候选就全被 `ang` 那一族占了）。全键拼音照旧按字母数。
- 一种解法都解不出来（按键不是这套方案的键、开了辅助码还大小写混用）→ `ParseError::NoSegmentation`：**不按全拼再读一遍**。
  一个例外：开着 `.cfg` 的 `mixture_input` 时，按键照旧按**原始按键**查一遍英文词（词表里有就只出英文候选）。

## 8. 校验与报错

- 判**整个方案无效**的情形：必填项缺失（含 `[Shengmu]` 缺节）、取值不在枚举里、文件不是 UTF-8、辅助码那一节写了 `Location` / `File`（已经不认这两项）、INI 里出现 `[Exchange]`（此节仅 TOML）、`[Shengmu]` 的左边不是零声母韵母 / 右边不是两键 / 两组撞键。
- 无效的方案在设置页用**红色文字**列出原因（`ThemeBrush::SystemCritical`）。
- 一个方案无效不影响别的方案，也不影响输入法启动（最坏情况退回全键拼音）。

## 9. 还没做 / 待定

- **辅助码文件的格式**：这轮认 `.tsv` / `.txt`（制表符两列）；`dat` / `csv` / `yaml` 还没做。
- **`Exchange` 的写法**（仅 TOML）：`[Exchange]` 节里一行 `swap = ["y-z", "a-b"]` —— 每个元素是一个「键-键」对。
  这轮只支持 TOML；INI 里出现 `[Exchange]` 判无效。
- **`;` 键的写法**：TOML 里要写 `";"`（裸键不允许 `;`），INI 里写**全角 `；`**（半角是注释）—— 两种都解析成同一个 `;` 键。
- **零声母不再有「通则」**：以前有「引导键 + 该韵母的键」的兜底，现在只认 `[Shengmu]` 里写死的两键 —— 写全了才打得出。
- **`[Info] RawInput` 已搬到配置**：`[input] show_raw_input`（缺省开，见 §6）。老方案文件里留着它 → 算**不认识的键**、整份无效。
- **内置样例**：带**首道双拼（默认）+ 小鹤双拼 + 自然码**三份；微软 / 搜狗 / 智能ABC / 小浪 这些键位方案后续手动加。
- **`[Shengmu]` 每个韵母只收一组键**（定死的）：上游小鹤 / 自然码的零声母各收了两种打法（`ai` 或 `ad`），
  内置样例各取「照原样」那一组；**暂不做多组**。
- `Version` 只做**迁移判据**（按最接近的旧语义容忍），还没有真正的版本迁移代码。
