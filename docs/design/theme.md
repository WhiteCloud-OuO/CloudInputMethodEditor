# 主题：三个窗口的颜色文件（2026-10-09）

候选窗口、悬浮工具栏、状态切换提示三个窗口的配色收进一份 JSON 主题文件；设置页「主题」页能选、能新建、能逐项改色，点「应用主题」（写进配置并重启输入法服务）后三个窗口一起换。

## 范围：这一版只有颜色

主题文件管 **21 个颜色**，别的还在代码里：

| 窗口 | 项数 | 内容 |
|---|---|---|
| 候选窗口 | 15 | 背景、高亮条、阴影、拼音串、拼音光标、高亮 / 普通候选文字、高亮 / 普通候选序号、页码、角标、翻译 Tip 的词性与分号 / 已学习 / 未学习释义、额外内容（在线翻译那一行等） |
| 悬浮工具栏 | 3 | 背景、图标、阴影 |
| 状态切换提示 | 3 | 背景、图标、阴影 |

- **字体**（拼音串 / 候选 / 序号 / 翻译）仍走「设置 → 候选」那四项，不进主题文件。
- **形状**——字号、留白、间距、圆角、**阴影的大小与模糊**——仍由渲染器的主题常量定，长度随系统 DPI 缩放（见 [rendering.md](rendering.md)）。主题文件只换阴影的**颜色**。
- **注解色**（`gloss` / `pos` / `fresh`）暂不进主题文件，用渲染器缺省。

先只做颜色，是把「文件格式 → 读写 → 热加载 → 设置页」这条链打通；字体与布局那几类参数等这条链稳定了再往同一份文件里加。

## 文件与优先级

- **两个目录**：随包 `<安装目录>\Themes\`（只读，升级 / 卸载会动这一棵）与用户 `%APPDATA%\CloudIME\Themes\`（可写，设置页新建 / 编辑的就是这里）。
- 两处都扫，**用户目录优先**：同名文件以用户那份为准，随包那份让位。这样用户改过的主题不会被装机包覆盖。
- 名字 = 文件名去 `.json`；`curr_theme`（`[theme]`）存**文件名**（`Default.json`）而不是路径，用户目录 / 随包由查找决定。下拉里显示去 `.json` 的名字（内置两份就叫 `Default` / `Panic`）。
- 随包给**两份内置主题**：`Default.json`（对齐现有观感，也是「新建主题」用来当底的那份）与 `Panic.json`（深色 + 橙色）。

## 文件格式

```json
{
  "candidate": { "background": "#FFFFFFFF", "text": "#D8000000", "…": "…" },
  "bar": { "background": "#FFFFFFFF", "icon": "#FF231F20", "shadow": "#5A000000" },
  "tip": { "background": "#FFFFFFFF", "icon": "#FF231F20", "shadow": "#5A000000" }
}
```

- 颜色一律 `#AARRGGBB`（也接 `#RRGGBB`，`#` 可省）。
- **缺键回缺省**（`#[serde(default)]`）：写个 `{}` 也能读（就是缺省主题），以后加键不会让老主题文件失效。
- 21 个键名与设置页 21 行的名字一一对应，映射写在 `apps/windows/settings/src/panel/pages/theme.rs` 的 `Slot`。

为什么是 JSON 而不是 TOML：这份文件由设置程序**整份重写**，没有 `config.toml` 那种「原地改键、保住用户注释」的需求；颜色又是定长字符串，JSON 写起来直白，`serde_json` 本来就在依赖树里（输入日志、更新检查都在用），不必为它再引 toml 的写入路径。

## 从改色到三个窗口换掉，这条链

1. 设置页「确认保存」：把草稿写进用户目录 `<名字>.json`（**只存不换**，可以连改几处再一次应用）。
2. 「应用主题」：把选中的主题名写进 `[theme] curr_theme`（同值也写），**并立刻重启输入法服务**。
3. **为什么要重启**：`curr_theme` 变了 Server 的热加载本来也会重读（它每秒看 `config.toml` 的 mtime），但**脚本临时换过的主题**（`cloudime.apply_theme` / 动作表 `theme`）只活在本进程里、热加载会保留它 —— 重启把进程换掉，配置里的这一份才一定说了算。保存与应用分成两个按钮，是为了让人「改够了再换」、也不会存一下就把窗口换了。
4. Server：`RouterConfig::render_settings()` 里 `load_theme(curr_theme)` —— 先 `find_theme` 定文件（用户目录优先），再按「**路径 + mtime**」缓存内容，命中就跳过读盘 + JSON 解析（目录扫描照做，它决定优先级）；找不到 / 读不动就用缺省主题。
5. `RenderSettings.theme` 变了，`Painter::configure` 整体重建：`apply_theme_colors` 把 21 项套到 `Theme.colors`，候选窗 / 工具栏 / 提示三份 `Shadow` 按各自的阴影色重建。
6. 画的时候候选窗用自己的阴影；状态条与状态切换提示经 `Painter::render_status(.., StatusKind::Bar / Tip)` 各取自己那套背景 / 图标 / 阴影；图标色由 `svg.rs` 的 `draw_svg` 按 alpha 把整张 SVG 染色。

脚本也能换主题：`cloudime.apply_theme("Panic")` 或动作表 `{ theme = "Panic" }` → 把名字写进 `[theme] curr_theme`
（`RouterConfig.curr_theme`）并**重启输入法服务**（与设置页「应用主题」同一套：重启才一定换上、选择也留了下来）；
`false` = 回本进程启动时那份（`Router.theme_at_startup`）。名字找不到时不写配置、不重启，只本次按缺省画、记一条日志。
**候选窗开着（正在组句）时挂起，等它关掉那一拍才写配置 + 重启**
（`Router.pending_theme` + `flush_pending_theme`）—— 免得正在看候选的人被整屏重画打断。
⚠️ 重启会换掉输入法服务进程（正在打字的程序断一下再连上，约 1–3 秒），别用在「每按一键换一次」的场景。

## 设置页「主题」页

自上而下：

1. **预览**：**用真渲染器出位图** —— 按草稿 + 配置里的字体拼一份 `cloudime_render::Theme`，画候选窗（拼音行、两条候选 + 角标、高亮、译文 Tip、页码、在线那一行）、悬浮工具栏（7 个真 SVG 图标）、状态切换提示（前 4 个图标），三块各自带主题阴影色，`encode_png` 后 1:1 贴出来。与真实窗口同一套渲染器，所以像素一致。
2. 「新建主题」按钮 + 名字框 + 「确认保存」按钮。
3. 「选择主题」标签 + 下拉（列两处目录里的主题名）+ 「刷新主题」「应用主题」「导入主题」「导出当前主题」四个按钮。
4. 21 行「颜色名 + `#AARRGGBB`」。

交互约定：

- 点某个颜色 → 弹颜色选择框（`color_dialog::ColorDialog`，`ContentDialog` + `ColorPicker`，带透明度）；「确定」后**只改草稿**，预览与那一行跟着变。
- 点「确认保存」**只写文件**（不换到它）：可以连改几处、觉得满意了再一次性应用。
- 点「应用主题」把下拉里选中的主题写进 `curr_theme`，**并立刻重启输入法服务**（几秒后新实例按配置换上它）；下拉没选中就提示先选一份。它不校验保留名（它只是把已有主题的名字写进配置）。
- 「新建主题」从内置的 `Default.json` 复制当底（找不到就内置缺省）；名字由纯函数 `theme_stem` 定 —— 名字框空着沿用当前选中的那份（改色保存），与随包两份内置主题同名（`Default` / `Panic`，大小写不敏感、带 `.json` 也认）的一律拒。
- 「刷新主题」重扫两个目录，新放进来的主题不重启就能看到。
- 「导入主题」挑一个 `.json`，先解析确认是主题再复制进用户主题目录，成功后自动刷新下拉并选中它（不自动应用）；与内置主题同名（`Default` / `Panic`）的同「新建主题」一样拒。
- 「导出当前主题」把当前草稿另存到用户挑的位置（不动用户目录里那一份），方便备份或分享。

## 还没做

- **字体 / 字号 / 圆角 / 留白 / 间距 / 渐变 / 透明 / 阴影形状**进主题文件。
- **注解色**（`gloss` / `pos` / `fresh`）进主题文件。
- **在线主题分享**（现在只有导入 / 导出文件，随包两份内置主题 `Default` / `Panic`）。
- **颜色写错的提示**：主题文件里一个颜色不合法，现在整份回缺省，没有指出来是哪一行。
