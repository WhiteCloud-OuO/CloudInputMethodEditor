# 候选窗口设计

## 布局

候选窗口缺省竖排（配置 `[general] layout`，可选横排）。竖排时每个候选项由两个主要部分组成：

```text
候选词                     翻译
```

例如：

```text
1  计算机                  computer
2  电脑                    computer
3  计算                    calculate
4  计算器                  calculator
```

候选词右侧可能再有一个浅灰小字标明来源：「短」是用户自定义短语、「句」是整句候选、「造」是用户自造词（已进用户词库），其余候选没有。
它用序号字体与固定的 `#888888`，右对齐在候选那一格里（与格右边缘留 4 pt）。

横排还可以展开成矩阵（固定 6 行视口 `GRID_ROWS`、按行滚动、数字键选高亮所在行），视口与列宽规则在 Core `candidate::layout::Grid`
（展示规则，壳只负责把视口里的格子按行优先排进帧），壳侧还没接，现在只做单行。

横排时候选排成一行，只给高亮的那个在下面单独一行显示译文（每个都带译文会把窗口拉得很宽），页码在行尾：

```text
1 计算机  2 电脑  3 计算  4 计算器          1/3
computer
```

顶部都有一行拼音（preedit），见下文「拼音行」。

## 视觉层级

- 候选词：较大、深灰
- 拼音串与候选项序号：纯黑（原先的半透明黑在白底上太淡、看不清）
- 翻译：较小、较浅
- 页码：弱化的灰
- 当前候选：轻量高亮

## 候选注解的规则

- 候选右侧可带一小段注解（如翻译、读音）；当前没有来源使用这一栏，字段保留。
- 没有注解时该行留空，不显示占位符，不显示「加载中」。
- 注解的具体取舍见 [architecture.md](architecture.md)。

## 技术选型

候选窗口本质上只有四个原语：若干行 (序号, 候选词, 译文)、一行高亮、跟随光标定位、异步补画译文。
这么小的 UI 不值得引入 GUI 框架。由一个 Rust 自绘渲染器出位图、壳只贴图（主题因此像素级一致），见 [rendering.md](rendering.md)；窗口的画法：

| 方案 | 说明 |
|---|---|
| Server 进程里自绘渲染器出位图、贴到 layered window（`server/src/ui/layered/`） | 候选窗与悬浮状态条共用一条 UI 线程与一个字体库，阴影、圆角都由渲染器画 |

不选的方案及原因：

- **WebView（水杉 HTML UI 的路线）**：样式最自由，但常驻进程多一个渲染引擎，首次弹窗有可见延迟，
  且引入平台运行时依赖。候选框是「打字时每秒弹好几次」的 UI，延迟比样式重要。
- **egui / iced / GPUI 等 Rust GUI 框架**：它们假设自己拥有窗口和事件循环，
  和「非激活浮层」这种系统级窗口语义打架，为几百行绘制引入整套框架不划算。

主题化通过主题文件（字体、字号、配色、行距、圆角、阴影、透明、渐变、布局）实现，不提供 HTML/CSS 皮肤；主题渲染的方向见 [rendering.md](rendering.md)。

## 平台层的职责

候选窗口由平台层绘制，但候选内容、顺序和译文全部来自 Core。
平台层拿到的是已经排好序、已经带好 annotation 的候选列表，只负责画。

## 按键约定

| 按键 | 行为 |
|---|---|
| 字母、`'` | 在光标处插入 |
| 空格 | 选上高亮候选并进组句（剩余拼音继续出候选）；无候选时上屏拼音 |
| 1 到 9 | 选上当前页第 N 个并进组句。这一页没有第 N 格（`gpt6` 只有三个候选）时数字当内容进缓冲区：中文模式成为英文直输段；英文模式是纯直通、数字归应用 |
| 回车 | 已选文本 + 剩余拼音原样上屏（去掉手敲的 `'`） |
| 退格 / Delete | 有已选文本、光标又在未选拼音末尾时先撤回最后一次选择（中文还原成拼音）；否则删光标前 / 后一个字母 |
| Esc | 清空（已选文本也不落文档） |
| 上 / 下 | 移动高亮，到页边自动翻页；第一项再按上不动 |
| Home / End | 拼音光标移到开头 / 末尾 |
| 左 / 右 | 移动拼音光标（不切模式）。光标只落在未选拼音范围内，进不了已选文本；光标停在中间时候选只按光标前的拼音算（`ni|hao` 出 你），剩余拼音留着、光标落到末尾；光标在开头或末尾按整段算 |
| PageUp / PageDown、Shift+Tab、翻页键（固定主键盘 `-` 上一页、`=` 下一页） | 翻页。每页几个由 `page_size` 定（1–9） |
| 可打印半角标点（`,` `.` `?` 等；`-` `=` 是翻页键，`_` `+` `'` 与 `` ` `` 除外） | 先把高亮候选选上、剩余拼音原样补完整体上屏，再按「没在组句」处理这个标点（符号映射 / 全角标点 / 成对补全）。高亮候选只吃掉一部分时，剩下的拼音也原样上屏，保证标点落得下去 |
| `_` `+` `'`（以及没有英文候选时的 `` ` ``） | 进**英文直输段**：`no-way` `hello,` `dui'ma?` 整段原样显示，之后的可见字符（含数字、大写）都追加，回车原样上屏，空格整段原样上屏后空格本身也交给应用（`hello, world` 的空格要在），Esc 清掉。表达式模式优先 |
| Tab | 翻到下一页 |
| 按住 Shift 打的大写字母 | 固定进拼音缓冲区，与小写一样参与匹配（`Shift` + `C` + `pan` → C盘），拼音行按敲的样子显示大写，原样上屏（回车 / 无候选）时还原大写；`Caps Lock` 亮着的字母仍是直通（只改大小写）。这一项不再可配 |

按音节删除、按音节跳光标的 Core API（`Engine::delete_syllable_backward` / `delete_to_start` / `move_cursor_syllable_left` / `right`）还没有配键，壳接上就能用。

### 整句转换（离线）

最优切分至少两个音节、且最优路径不止一个词时，整句作为 `CandidateKind::Sentence` 候选与词 / 英文候选一起按权重排（不再无条件第一位；空格上屏当前首选）：
`jintiantianqihenhao` → 今天天气很好，`womenyiqiqukaifa` → 我们一起去开发。整段本身是词库里的词时不出整句。
打分是静态 bigram（`cloudime-lm`）与个人 n-gram（二元 + 三元，看前两个词）插值。简拼位置照转（`jttqhh` → 今天天气很好，`wjdzjsg` → 我觉得自己是个），
每个简拼格子按前缀多留一些词、由语言模型挑读音；两字母简拼多半还是词（`sj` 时间），单词路径得分高就不出句子。
全拼句子末尾未打完的音节至少两个字母才算进句子（`woxiangs` 多半是没打完的 shuo），前面已有简拼的句子末尾单字母就是一个音节（`wxq`）。
有音节连单字都查不到（只能拿拼音占位）的不出句子。中文词、整句与英文候选一起按权重降序、文本升序排：
英文权重 = 词频 × (1 + 选过次数)，没有词频按 1.0，不再固定排在中文后面（2026-09 曾固定中文优先、删了 `chinese_first` 开关，现改回按权重）。
上屏按音节消耗拼音，路径上的词逐条记进个人 n-gram（`user-ngram.tsv`），不记词频。

**句末英文词**（`Engine::split_english_tail`，`query::EnglishTail`）：整段末尾是英文词表里的词、前面能切成完整拼音时，
整句是头段的转换加上那个词（`woxiangxuehaorust` → 我想学好rust），与其他候选一起按权重排，`Query.tail` 是尾段字母（拼音行 `wo'xiang'xue'hao'rust`），
词级候选只按头段查。整段字母根本切不成拼音的（`wodetv` 的 v、`woyongvim`）直接按英文读；整段也能读成拼音的
（`woxiangxuehaorust` 读成 … ru s… t… 简拼、`wodedatabase`）两种读法比分：头段整句分 + 英文词 log 概率（wordfreq Zipf 换算，
没词频按 Zipf 3）− 切换代价（`ENGLISH_SWITCH_PENALTY` 3 nat，拍的）要高过整段按拼音读的整句（`sentence::convert_whole`，
末尾单字母也读，`huoz` → 或者，两边覆盖同样多的字母才公平），赢了按英文读法出候选（拼音读法也进池子），输了英文读法不出
（`womenqubeijing` 只有 我们去北京，`diaoyong` 不出 掉Yong）。尾段自己是完整拼音的（`fan`）要至少 4 个字母，
两个字母的尾段只认缩写词（ID / TV）和个人表里的词；整段是英文词（`agent`）、拼音不像话时能纠错（`shiide` → 是的）或有英文补全
（`releas`）的不切。同时满足的取最长尾段。上屏时英文词是路径上最后一个词（音节就是敲的字母），进个人 n-gram，
并记进个人英文词表。回放（2026-09-08，4867 条）与改前持平：词 86.0% / 整句 89.3% / 英文 69.8%。
只认句末，夹在中间的英文（`wozaidebugzhege`）要等词图上加英文边。

**越用越像自己**：连续上屏的词（整句里的、或一个个选的）都记成「前词 → 后词」，同时记「前二词 前词 → 后词」；`yun` 里选过两次 云 + 朵，
再打 `yunduo` 整句就直接出 云朵（个人转移压过静态模型里的同音候选）。三元分辨二元混在一起的接续：「我想」后面选过几次 区，
`woxiangqu` 就出 我想区，而「不想」后面照旧。标点、回车上屏拼音、切应用都断句，之后的词按句首记。
**自动造词**：自己连着选出的两个词合起来词库里没有（不超过 4 个字），同一段拼音里连着选两次、或分两段打两次，
就记成用户词（`UserWordBank.db`，缺省在安装目录的 `WordBank\` 下，初始权重 = 各字词库词频最大值、之后每次重选涨两成），之后按词出、靠权重排前。

### 英文模式是纯直通

英文模式（单击 `Shift`、语言栏 / 状态条上的「英」切进去，全局一份）下云朵输入法**不再接管输入**：字母、数字、
标点、空格、回车全部直接交给应用，不组句、不出现候选窗口，与没装输入法时一致——终端与代码编辑器里的补全、
`Tab`、方向键不会被占掉，因此也不再需要按应用关候选的 `[apps]` 名单。
壳侧 `eats_key` 的字母分支在英文模式 / `Caps` 亮着时放行（只有组句中的字母仍吃，拼音要接着写下去），
服务端 `apply_english` 的字母分支直接回 `Effect::Passthrough`；标点、数字仍先「测吃」送去服务端按英文那份
全角开关转（缺省半角、不转，回 `Passthrough` 再放行）。
缓冲区里还留着上一段拼音时，先把拼音按敲的样子原样上屏，再连同这个字母一起由我们插入
（Windows 放行是同步的、上屏走异步编辑会话，分两步会让应用先插字母再插词）。
英文词的补全与拼错纠正改在**中文模式**里给（见下节与「中英混输」），进英文模式只意味着「这几下要原样打」。

**个人英文词表**（`user-english.tsv`，`词\t次数`）：随包词表只有两万多词，`gist`、`kubectl` 这类不在里面的词以前永远出不了候选。
现在原样上屏的字母串只要像英文词——纯字母、至少两个，中文模式下还要**切不成完整拼音**（`hao` 回车多半要的是字母本身，不学；
`gist` / `python` / `hello` 切不干净才是英文）——就记进个人词表，选中英文候选也记。英文候选由个人表 + 随包表一起出，
个人表在前：精确词取第一个有的，补全与纠正合在一起按选过的次数、词频排（`Engine::english_lists`、`english::suggest` 收词表列表）。
所以 `gist` 回车一次，下次敲 `gist` 它就是首选。

### 英文补全（中文模式）

- **英文补全**：整段输入切成的拼音「不像话」（切不动、或非末尾有简拼 / 残缺音节：`compa` → `co'm'pa`、`impor` 连第一个字母都切不动）
  且至少 3 个字母时，除了整段正好是的英文词，还出词表里该前缀下最常用的 3 个（`compa` → company / companies / compared），
  紧跟在精确词之后、排在拼音候选前。干净的拼音（`xian`、`shan`）不补全，免得每个音节都冒英文。词频来自 wordfreq（`tools/corpus/english_frequency.py`）。

### 模糊音（默认全关，`config.toml` 的 `[input] mo_hu_yin_list`）

开了 z/zh 之后敲 `zi` 也出 知 / 之，开了 n/l 敲 `lan` 也出 南，开了 f/h 敲 `kaiha` 也出 开发；韵母那两组（`ng/n`、`ü/u`）
只对完整音节生效（末尾没打完的音节本来就按前缀查，`fen` 自然出 feng 的字）。敲对的词仍然优先：模糊命中的词频减半参与排序，
同分排在后面。简拼位置也套声母规则（`zh` 前缀开了 z/zh 就按 `z` 查），整句转换用同一套写法。
配置里是一张位图（见 `MO_HU_YIN_BITS`），设置页「输入」勾选。CLI 用 `--fuzzy z-zh,n-l` 或 `--fuzzy all` 临时开。

### 快捷候选（搜狗 v 模式）

Core `shortcut` 模块，不查词库、由输入直接算出，`CandidateKind::Shortcut`，上屏吃掉整段作用域、不记学习：

- `rq` / `sj` / `xq`：今天的日期（`2026年9月3日`、`2026-09-03`、`2026/09/03`）、现在的时间（`19:06`、`19:06:23`、`19点06分`）、
  星期（`星期四`、`周四`），插在本地首选之后（首选仍是 日期 / 时间 / 需求 这类词库词）。
- 表达式键 `v`（`EXPRESSION_PREFIX`，固定）开头进**表达式模式**：不解析拼音，preedit 原样显示。`v1+2` 出 `3` 与 `1+2=3`（支持 `+ - * x / ^`、括号、小数），
  `v123` 出中文数字小写 `一百二十三` 与大写 `壹佰贰拾叁`，再跟金额 `一百二十三元整` / `壹佰贰拾叁元整`；
  `v123.5` 出小数读法 `一百二十三点五` / `壹佰贰拾叁点伍` 与金额 `一百二十三元五角` / `壹佰贰拾叁元伍角`（小数超过两位只有读法，`shortcut::number_forms`）。此时**数字和运算符进算式而不是选词 / 翻页**，
  选第二项用上下键 + 空格；回车上屏原文；`v` 开头的英文词（`very`）仍走中英混输。

表达式前缀固定为 `v`（不作为任何拼音音节的开头，搜狗 / 微软同一思路：一键进模式、不要修饰键、中文模式下零冲突），不再提供配置。
没采用水杉的 Shift+字母模式键：Shift+字母固定进拼音缓冲区（按小写匹配、原样上屏时还原大写），而且 Shift 单击留给切中英。

### 悬浮状态条与设置程序

配置文件 `config.toml` 是唯一事实源；悬浮状态条、设置程序、手改文件三个入口都只写它，Server 再热加载
（每秒看一次修改时间，连词库目录的增删一起看；保存后一秒内生效，不用重切输入法）。

悬浮状态条是桌面上常驻、可拖动的图标条（常开，没有开关；禁用或全屏时收起），一排按钮：中 / 英（Caps Lock 亮着显示大写锁定那张）、中文标点 / 英文标点
（中英各记一份，会话内状态、不进配置文件，重启回缺省）、全角 / 半角（直通字符转全角，同样是会话内状态）、简 / 繁（写 `[input] simp_trad_chinese_chars_toggle`）、设置；
工具页与特殊字符页的按钮先摆着，程序还没做，点了只记日志。按钮的顺序、显隐与图标来自 exe 旁 `data\icons-arrangement.cfg`（`pos` 定位置，`-1` 不显示，
图标是 `data\icons\` 下的 20 px SVG），改完存盘下一次重画就重读；按下鼠标先 `DragDetect`，挪出阈值就交给系统拖动、没挪就是点击。
开关与记住的位置在 `[status_bar]`（`x` / `y`，状态条常开，只跟「当前输入法是不是云朵输入法」走），热加载即时生效；前台是否全屏时自动收起由 `[debugging] auto_hide_float_tool_bar` 定（缺省开，关掉后全屏也不收，切输入法仍收）；只在当前输入法是云朵输入法时显示
（见 [architecture.md](architecture.md) 的「悬浮状态条」）。

设置程序 `cloudime-settings`（窗口标题「云朵设置」）是左侧导航 + 右侧表单的窗口。结构是「输入 / 候选 / 词库 / 短语 / 调试」
五页（前四页与四个配置分节一一对应，调试页放实验性开关与统计面板），已经全部搬完：「输入」（`[input]` 的八项：使用简拼、模糊音勾选、
简体 / 繁體单选、中英文混合输入、标点符号全 / 半角下拉、中文模式下符号映射（只读列表，在配置文件里改）、符号成对补全、数字后标点使用半角）、
「候选」（`[candidate]` 的十项：本地整句模型、排布单选、个数滑轨 5–9、联想候选项目上限 0–4、三个「字体…」按钮弹系统字体对话框、序号样式下拉、
最小宽度、展示更多候选项（功能未做）、按程序隐藏名单；另加拼音显示位置），其余页是：

### 中英切换

切中英：单击切换键在中 / 英之间翻转。切换键写死为**单击 `Shift`**（`InputSettings::switch_mode`，缺省值下发给 DLL，
设置里不再提供选择）；任务栏语言栏与悬浮状态条上的「中 / 英」按钮同样能切。
系统自带的 `Ctrl + Space`（输入法 / 非输入法切换）是**禁用 / 启用**（三态 `InputMode`，不是切中英）：禁用后完全不接管、状态条收起、任务栏图标变「禁」，
重新启用回到禁用前的中 / 英。
中英模式所有应用共用一份；内置英文模式不再可关（`InputSettings::english_mode` 恒为 `true`，语言栏按钮照常登记）。

内置热键（固定，不落配置）：`Shift + Space` 翻全角 / 半角、`Ctrl + Alt + ,` 翻中文 / 西文标点、`Ctrl + Alt + .` 翻简 / 繁；
悬浮状态条上对应的三格与它们走同一条动作（`dispatch/status/mod.rs::handle_status_event`）。

英文模式靠**单击切换键 / 语言栏**进入，`Caps Lock` 不参与模式判定：它只是大小写位，亮着时字母按 `shift XOR caps`
交给应用（`KeyModifiers` 里 `caps` 是大小写位、`english_mode` 是持久模式位，两个都不是物理键），
中英模式与标点的全半角都不看它；亮着时单击 `Shift` 会先取消大写锁定、再切英文。默认小写、按住 `Shift` 大写。机制细节见 [architecture.md](architecture.md) 的「中英模式」。

中文标点：`, . ? ! : ; ( ) [ ] < > \ ^ _ $ ~` 转全角，`"` `'` 成对切换；数字后的 `.` 保持半角。
`-` `=` 不转换，但**由壳自己插入**、不走放行：放行要等宿主把键交回应用，实测在部分宿主（Edge / QQ 等）
里这个键到不了应用，表现为「中文模式按 `-` 没反应」；插入与全角标点同一条路（`dispatch/key/input.rs` 的
`apply_punctuation`），一定是半角的 `-` `=`。

### 拼音行（preedit）

候选窗口顶部有一行 preedit：带 `'` 的切分拼音和我们自己画的光标。marked text 里的插入点由应用决定画不画，
终端和不少 Electron 应用不画，所以光标必须自己画。
Core 给的是分段（`Query::marked_segments`，`MarkedKind`：敲的拼音 / 光标后剩下的拼音；`MarkedKind::Corrected` 仍留给别的调用方，但纠错不再整段替换切分，`query` 不再产生它），
壳按段选样式（敲的拼音正常、光标后的剩余画淡），光标位置按拼接后的字符数算。

### 拼写纠错

拼音「不像话」时（切不干净有尾巴，或非末尾的音节里有简拼 / 残缺）或末尾落单一个字母时，试一处编辑：**相邻换位**与**键盘相邻键替换**（`engine/query/spelling.rs`）。
换位的变体放宽到「只有末尾一个音节没敲完」（`correction::loose_segmentation`，按解析器偏好取第一种切法：`mignt` → `ming t…`、`migntia` → `ming tia…`），
敲反两键的人多半还在往下敲；替换只留相邻键、要求每个音节都完整。删除 / 插入两类不再做。变体先过无分配的 `parser::is_fully_segmentable` /
可达性检查，剩下几个才做真正的切分；仅末尾落单字母触发时只试换位，省每键的变体枚举。
这些纠正读法与原样读法**进同一个候选池**，不替换原样：折扣是换位 0.75、替换 0.70；原样输入本身能整段对上一个词 / 短语时保留折扣，否则再乘 1.2 / 1.15，
让明显敲错的串更容易被纠。合法简拼（`nhao`、`womend`）不会被误纠；整段本身是英文词的不纠（`hello`）；「删掉刚敲的最后一个字母」不算纠正（`kaiv` 的 v 留作尾巴）。
2026-09 之前的两套噪声信道纠错（整段替换 + 词图敲错边）已删，只保留这套权重打折。

**词图敲错边已删**（2026-09）：以前整句词图里每个完整音节还按一处敲错变体（`correction::typo`）查词、命中的词扣代价，
管「音节都合法、整句却说不通」的输入（`meiganxi` 读成 没关系）。现在词图只加模糊音写法；`meiganxi` 这类合法拼音不再被读出别的词，
`correction::typo` 的变体表只剩 commit 对齐用（`Engine::align`），不参与打分。
上屏时候选音节逐个对回敲的字母（`Engine::align`：原样、没打完、模糊音或敲错变体、公共前缀——没打完排在变体前，`shijia` 选 时间 不算把 `jian` 敲成 `jia`；先找能把每个音节都对上的对齐，带回溯——
`pingyin` 上屏 拼音 时 `pin` 原样只吃三个字母会剩下 `gyin`，退回来按 `ping` → `pin` 吃四个，2026-09-17），按敲的字母消耗，
靠敲错变体对上的、以及上屏纠错读法落在的那个音节（`Correction::typo_pair`）的 (敲的, 要的) 音节对记进**个人敲错表**
（`user-typos.tsv`，`Learner::record_typo`），退格重选时退回。敲错表现在只记录、不再参与打分——「个人按键混淆模型」以后要接回排序得另做。

纠错读法的候选与原样读法在同一个池子里，拼音行按敲的字母原样显示、不画删除线；
选纠错读法的词时按那处编辑换算消耗的原串长度（换位 / 替换不改长度），再按原输入串记选择（`user-choices.tsv`），下次同样敲错它更靠前。
**回车仍原样上屏** `nihooma`。`Query::correction` 从此恒为 `None`；`correction` 模块只描述一处编辑的读法，挑选与学习在 Engine 里。
